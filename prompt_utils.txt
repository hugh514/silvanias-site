Estou desenvolvendo o site "Silvania's Cacau", uma vitrine virtual para uma
empresa artesanal de chocolate, com painel administrativo.

STACK
- Next.js 14+ (App Router) + React + TypeScript
- Tailwind CSS
- Supabase (PostgreSQL, Auth, Storage) — usando o novo sistema de chaves
  (publishable key / secret key, não mais anon/service_role)
- Vercel (hospedagem)

ESTRUTURA DE PASTAS
app/
  page.tsx                     → vitrine (página principal)
  admin/
    login/page.tsx
    produtos/page.tsx
    produtos/novo/page.tsx
    produtos/[id]/page.tsx
  produtos/
    [id]/page.tsx               → página pública do produto
components/
  ui/        → componentes reutilizáveis
  vitrine/   → componentes da vitrine
  admin/     → componentes do painel
lib/
  supabase/
    client.ts       → cliente frontend (publishable key)
    server.ts       → cliente backend (secret key)
    proxy.ts    → lógica de sessão usada no middleware
middleware.ts        → protege rotas /admin (redireciona não logados
                        para /admin/login e logados para longe do login)

BANCO DE DADOS (tabela `produtos`)
id uuid, nome text, categoria text, descricao text, ingredientes text,
preco numeric(10,2), unidade text ('peso'|'volume'|'unidade'),
valor_unidade text, disponivel boolean, fotos text[], created_at timestamptz

SEGURANÇA (RLS)
- Leitura pública (qualquer visitante lê produtos, sem login)
- Escrita só para usuários autenticados
- Não existe cadastro público de usuários — único usuário é o admin,
  criado manualmente no painel do Supabase (signup público desabilitado)
